📋 팀 프로젝트 개발 규칙
##  1. 브랜치
브랜치 구성
main        : 최종 배포
develop     : 개발 통합
```text
feature/{예시}
feature/refrigerator
feature/airconditioner
feature/dehumidifier
```
작업 순서
develop    ->    feature/본인기능    ->    develop Merge

❌ main 브랜치에 직접 Push 금지
조장이 develop에서 main으로 직접할것

## 📂 2. 패키지 구조

```text
com.프로젝트명.도메인명
│
├── board
│   ├── dto
│   ├── mapper
│   └── service
│
├── client
│   └── board
│       └── controller
│
├── common
│   ├── config
│   ├── dto
│   └── util
│
└── main
    └── controller
```

### Resources

```text
resources
├── mapper
├── static
└── templates
```

> **규칙**
>
> - Java 클래스는 `src/main/java`에서 관리합니다.
> - Mapper XML은 `resources/mapper`에서 관리합니다.
> - HTML은 `resources/templates`에서 관리합니다.
> - CSS, JavaScript, 이미지는 `resources/static`에서 관리합니다.

## 🏷️ 3. 클래스 네이밍 규칙

| 구분 | 예시 |
|------|------|
| DTO | `LaptopDTO` |
| Mapper | `LaptopMapper` |
| Mapper XML | `LaptopMapper.xml` |
| Service | `LaptopService` |
| ServiceImpl | `LaptopServiceImpl` |
| Controller | `LaptopController` |

> **규칙**
>
> - 클래스명은 **제품명을 접두어**로 사용합니다.
> - Interface와 구현체의 이름을 동일한 규칙으로 작성합니다.

## 🌐 4. URL 규칙

### 일반 CRUD 방식

```text
/{제품명}/list
/{제품명}/detail
/{제품명}/write
/{제품명}/update
/{제품명}/delete
```

예시

```text
/laptop/list
/laptop/detail
/laptop/write
/laptop/update
/laptop/delete
```

---

### Path Variable 방식 (권장)

```text
/{제품명}/list
/{제품명}/{id}
/{제품명}/write
/{제품명}/update/{id}
/{제품명}/delete/{id}
```

예시

```text
/laptop/list
/laptop/1
/laptop/write
/laptop/update/1
/laptop/delete/1
```

> **규칙**
>
> - 프로젝트 시작 전에 URL 규칙을 하나로 통일합니다.
> - 새로운 기능을 추가할 때도 동일한 규칙을 유지합니다.
프로젝트 시작 전에 하나로 통일합니다.

15. Merge 전 체크

☑ 컴파일 오류 없음
☑ 서버 실행 확인
☑ 기능 테스트 완료
☑ 불필요한 import 제거
☑ Console 출력 제거
☑ 사용하지 않는 코드 삭제

16. 팀원 간 약속
다른 사람이 만든 파일은 허락 없이 수정하지 않는다.
***공통 클래스(Common, Config 등)는 팀원과 상의 후 수정한다.
DB 변경 사항은 팀원에게 먼저 공유한다.
Merge 전에 최신 develop 브랜치를 먼저 반영한다.
