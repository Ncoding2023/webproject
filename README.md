📋 팀 프로젝트 개발 규칙
##  1. 브랜치
브랜치 구성
main        : 최종 배포
develop     : 개발 통합
```text
feature/{예시}
feature/refrigerator
feature/airconditioner
feature/dehumidifier
```
작업 순서
develop    ->    feature/본인기능    ->    develop Merge

❌ main 브랜치에 직접 Push 금지
조장이 develop에서 main으로 직접할것

## 📂 2. 패키지 구조

```text
com.프로젝트명.도메인명
│
├── board
│   ├── dto
│   ├── mapper
│   └── service
│
├── client
│   └── board
│       └── controller
│
├── common
│   ├── config
│   ├── dto
│   └── util
│
└── main
    └── controller
```

### Resources

```text
resources
├── mapper
├── static
└── templates
```

> **규칙**
>
> - Java 클래스는 `src/main/java`에서 관리합니다.
> - Mapper XML은 `resources/mapper`에서 관리합니다.
> - HTML은 `resources/templates`에서 관리합니다.
> - CSS, JavaScript, 이미지는 `resources/static`에서 관리합니다.

## 🌐 4. URL 규칙

### 일반 CRUD 방식

```text
/{제품명}/list
/{제품명}/detail
/{제품명}/write
/{제품명}/update
/{제품명}/delete
```

예시

```text
/laptop/list
/laptop/detail
/laptop/write
/laptop/update
/laptop/delete
```

---

### Path Variable 방식 (권장)

```text
/{제품명}/list
/{제품명}/{id}
/{제품명}/write
/{제품명}/update/{id}
/{제품명}/delete/{id}
```

예시

```text
/laptop/list
/laptop/1
/laptop/write
/laptop/update/1
/laptop/delete/1
```

> **규칙**
>
> - 프로젝트 시작 전에 URL 규칙을 하나로 통일합니다.
> - 새로운 기능을 추가할 때도 동일한 규칙을 유지합니다.
프로젝트 시작 전에 하나로 통일합니다.

## 🎲 9. DB 컬럼명 규칙

### 필수 컬럼

```text
id 또는 no
created_at
updated_at
```

### 예시

```sql
no          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
created_at  DATE DEFAULT SYSDATE,
updated_at  DATE
```

### 규칙

- PK는 `id` 또는 `no` 사용
- 컬럼명은 **snake_case** 사용
- 생성일 : `created_at`
- 수정일 : `updated_at`
- 필요한 경우 `NOT NULL` 적극 사용

## 🤝 16. 팀원 간 약속

- 다른 팀원이 작성한 파일은 허락 없이 수정하지 않습니다.
- **공통 클래스(`common`, `config` 등)는 반드시 팀원과 상의 후 수정합니다.**
- DB 변경 사항은 팀원에게 먼저 공유합니다.
- API(URL) 변경 시 관련 담당자와 함께 확인합니다.
- Merge 전 최신 `develop` 브랜치를 먼저 Pull 받은 후 작업합니다.
- 충돌(Conflict)이 발생하면 임의로 해결하지 말고 담당자와 함께 확인합니다.
